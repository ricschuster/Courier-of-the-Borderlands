## The two findings

### The wear harness was wrong by 4.5x

Built to price Ashmoor's difficulty, it read `speedModifier` where the game reads
`wearSpeedModifier` (ADR 0005: roads move at 1.2x but pin wear roughness to 0).
It reported the paved entry road at **76% of a level-1 tank**. The real figure is
**9%**.

Believed, that would have meant softening a region that is correctly tuned. It
was caught by refusing to trust any Ashmoor number until the harness reproduced
v43's measured 1.80 for leaving the Greybridge hub. It printed 8.23, and the gap
was the whole finding.

**The general form: a measurement tool needs a known-answer calibration before
its unknown answers mean anything.** This is trap 1 pointed at analysis rather
than tests, and the calibration cost about five minutes.

Final figures, bare wagon against the 25-point level-1 tank, standard:

| Leg | Wear | % of tank |
|---|---|---|
| Either gateway -> Emberfast | 2.3-2.4 | 9-10% |
| Emberfast -> Cairnwatch | 13.7 | 55% |
| Emberfast -> Windfall | 14.9 | 60% |
| Emberfast -> Blackreed | 23.2 | 93% |
| Emberfast -> Sallowmere (long way) | 49.8 | 199% |

Arriving is nearly free from either side, so nothing is an exit lock; a level-1
courier gets about one delivery out of the place before stranding.
`wearMultiplier: 2.0` is an estimate from the model, **not a felt judgement**.

### The survey ring is invisible unless the minimap is open

The minimap starts hidden (`map-hud.ts:183`) and `redrawMinimap` only runs while
it is open. So the ring can go an entire run without being on screen once.

Found by accident: the first version of the #425 teach triggered off the minimap
model, passed its unit tests, and **did not fire at all** in the browser. That
failure is the better half of the #425 diagnosis. A teach that waits for the
minimap to be open would have reached mostly the players who had already found
the thing.

The trigger now takes raw state, fires with the map closed, and the message says
which key to press.

The band itself was 0.4 alpha over near-black, which reads as a fog gradient
rather than a category. Alpha alone could not fix it: raising it just makes
surveyed ground look like walked ground. It is now 0.75 alpha **and inset by a
pixel**, so walked ground is continuous and surveyed ground is separated. That
was confirmed by capturing before/after on a real boot, because no test can see a
legibility fix.

## Verification notes

- **Neutralized six times across two PRs**, each watched failing before
  restoring: breaking a ring link drops the route-count guard to one route;
  moving a gateway one tile fails the browser arrival assertion; inverting the
  teach trigger fails both browser guards in both directions; the plausible wrong
  teach rule fails two unit guards; deleting the teach call site fails the build.
- **CI caught what the full local gate could not.** Lint, 1322 unit tests and all
  59 browser specs were green locally, and `check` still failed: the survey-ring
  pricing test runs a router over every contract route in every region, and a
  fourth region pushed it past vitest's 5s default **only under `--coverage`**,
  which CI runs and `npm test` does not. Instrumentation takes that file from
  0.3s to 2.6s. Run `npx vitest run --coverage` before trusting a green suite on
  anything that adds content.
- **The ring did not break autoplay**, which was the real risk worth checking now
  that the gateway graph has a cycle: it terminates cleanly rather than looping.
  It does stall in Saltreach, but on a route this session did not touch
  (`region-saltreach.ts` is byte-identical), so that is trap 5's known false
  signal, not a regression. Tracked as #440.
