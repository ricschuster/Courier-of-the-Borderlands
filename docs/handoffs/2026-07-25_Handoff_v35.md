## Decisions taken

1. **#372 took the hint cluster, not one of the three #370 measured.** #370
   deliberately made no recommendation. The hint line was chosen because it was
   the largest genuinely pure thing still inline, and because `modalHintText` (the
   same screen surface in its other state) was already a pure builder in
   `panel-text.ts` while the world hint was assembled by hand. Recorded on the PR.
2. **The #373 recommendation changed after measuring.** The session had suggested
   splitting `update()`. Measurement killed it: the phases become private methods
   on the same class, so the file stays the same size. Save/restore was
   recommended and taken instead, because it moves lines out *and* yields tested
   rules.
3. **`save()` deliberately stays in the scene.** A pure snapshot builder would
   take the same 17 live fields `save()` already reads, so it would re-list them
   and buy nothing. The rules worth testing are all on the read side. This is why
   #374's net was 31 lines, not #365's 108.
4. **`wagonHintText` reuses `RepairHelpInput` rather than inventing a type.** It
   and `repairHelpText` are counterparts on the same four facts: one quotes the
   price before the press, the other explains a press that could not pay it.
5. **The input handlers are deliberately last.** 302 lines, the biggest group, but
   mutually unrelated: a repair press and a scroll press share only that a key
   fired. A host interface would relocate them behind a `this.host.` prefix and
   yield no testable logic, which is the trade #365's guardrail warns against.
