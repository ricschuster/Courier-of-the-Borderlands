## Decisions taken

1. **Cut the release before the playtest, not after.** #363 asked for a playtest
   on 0.7.0, which predates all 37 cues and the bed. Releasing first means the
   playtest that happens is the one that can judge the audio, while retuning is
   still rows of numbers in `audio-cues.ts` rather than an asset job.
2. **Extract by shared state, not by shared prefix.** #392 proposed taking the 15
   `refresh*` methods as a unit. That framing turned out to be wrong: most are
   already thin adapters over pure builders in `systems/`, so moving them would
   need an accessor-per-statistic host and buy nearly nothing. The milestone
   cluster was taken instead because five scene fields moved with it. The next
   slice should be chosen the same way.
3. **One `RunStats` snapshot instead of fifteen host accessors.** Every milestone
   surface derives from the same numbers, so `MilestoneHost` stayed at eight
   members. This also removed real duplication: `achievementStat()` and the
   telemetry record were separately reading the same eight fields.
4. **The milestone controller is built at the top of `create()`**, not beside the
   other two, because `restoreState()` hands it the loaded save. Its host reads
   through closures, so the HUD and audio it needs may arrive later.
5. **Spending stayed in the scene.** `handleSkillInput`, `handleUpgradeInput`, and
   `buyUpgrade` are not panel input in the sense slice one used: they spend points
   and coins, so they group with the economy.
6. **A controller that imports the Phaser runtime cannot be unit tested.** Phaser
   fails to import under the `node` test environment, so `BoardInputController`
   takes "was this key just pressed" through its host instead of calling
   `Phaser.Input.Keyboard.JustDown`. That is what made the arm/confirm rules
   testable. `PanelInputController` still calls Phaser directly; it is pure
   dispatch with no owned state, so the payoff there is smaller, but the same
   move is available if it ever needs coverage.
7. **The board slice was picked from a measured survey, not a hunch.** The initial
   guess was to take the whole contract/board group. Measuring coupling per
   candidate cluster showed that grouping scored worst of eight (13 outside
   methods, plus a `boardContracts -> effectiveFlags -> regionCleared ->
   baseContractCounts -> completed` cycle). Splitting it and taking only the
   board half scored 2.

## Verification notes

- **Three coverage holes found in two slices, all the same shape.** Each was a
  path where neutralizing the code left the entire suite green:
  1. The region-cleared summary's **Esc dismissal** had no coverage anywhere. Its
     capstone twin did, which is what made the gap worth checking rather than
     assuming.
  2. **`restore()`** as a no-op. The regression it hides is specific:
     `blockadeBrokenAtLoad` stops being set, so every reload of a finished save
     replays the finale.
  3. **`resetForNewRun()`** as a no-op. That is #291's fix, unguarded.
- The pattern is consistent enough to state plainly: **this file's surfaces are
  verified on the path that creates them and not on the path that reloads them.**
  Worth assuming the same on every remaining slice.
- All three are now covered, and each was re-neutralized afterwards to confirm the
  new test fails. The unit tests exist only because the extraction made them
  possible: that state was previously reachable only through a running Phaser
  scene, which is the payoff #392 predicted.
- **The #393 flake was classified before being chased**, per trap 4. It failed on
  the first two full-suite runs of the refactor branch, which looked causal.
  Sampling both sides showed otherwise: branch 3 failures in 8 runs, `main` 1 in
  7, same spec and same `encounter-start` trace. The first three `main` samples
  were all green, which is exactly why one clean run proves nothing.
- **A neutralization was watched to "pass", and the result was a lie (#397).**
  Arming was removed from the contract board and `board-confirm.spec.ts` passed,
  despite that spec asserting the armed state directly. Cause: the suite never
  built the working tree. `playwright.config.ts` hardcodes port 4173 and sets
  `reuseExistingServer` locally, so when a second checkout is already serving that
  port, Playwright skips `npm run build` and points every spec at the other tree's
  build. This is trap 1 in a costume the guidance does not cover, and it fails in
  the dangerous direction: the neutralization looks *irrelevant*, which invites
  the conclusion that the code is dead. Any session running a worktree agent, a
  second checkout, or leaving a stale `vite preview` alive is exposed.
- **Every PR ran the full browser suite**, not just the arc.

## Risks or decisions needed

- **Nobody has still heard the audio at volume.** Unchanged from v37 and now
  shipped to players in 0.8.0. The bed remains about three times quieter than its
  commanded numbers read, and that is still the single most likely thing to be
  wrong.
- **`create()` is becoming the next `map-scene.ts`.** It is around 210 lines and
  takes another host literal with every slice. The extraction pattern moves ~150
  lines of logic out and puts ~40 lines of wiring back, so the file shrinks while
  `create()` grows. Worth watching whether the host wiring itself needs a home
  before the fourth slice.
- **`create()` now builds three host literals before the HUD exists.** Two of the
  three controllers must be constructed at the top of `create()` because
  `restoreState()` writes into them, and their hosts only work because every
  member reads through a closure. That is load-bearing and unobvious: a host
  member that captured `this.hud` eagerly instead of `() => this.hud` would be
  undefined at construction and fail at runtime, not at compile time. Worth a
  comment surviving into the next slice, which it now has.
- **The refactor is behaviour-preserving by assertion, not by proof.** The suite
  is the only guard, this session found three places where the suite would not
  have noticed, and #397 showed the guard itself can be pointed at the wrong
  build. Each slice should keep neutralizing rather than trusting green, and
  should confirm the neutralization actually reached the browser.
