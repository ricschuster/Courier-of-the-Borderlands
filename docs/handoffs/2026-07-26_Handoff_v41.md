## Decisions taken

1. **The audio ships as tuned.** The bed peaks at roughly a third of its commanded
   level because bandpass-filtered noise carries far less peak energy than its
   envelope ceiling. The commanded numbers are what the tests pin, and a human ear
   says the result sits right, so they stay. #226 Phase 2 no longer carries a
   pending-judgement caveat.
2. **Gate the arc on an upgrade fitted, not a coin price.** An upgrade cannot be
   spent away once bought, so the gate can only ever be ahead of the player once.
   A coin-priced gate can be paid past and then re-encountered after a bad repair
   run, which is the shape that actually strands people.
3. **Do not extract `create()`'s host wiring.** The host literals close over
   private scene fields, so moving them out means either widening those fields to
   public or inventing an interface to read them through. The literal is currently
   the *narrowing*: it is the explicit, documented coupling surface. `create()` is
   linear construction, not the interleaved rules-and-rendering that made the file
   worth slicing, and ADR 0009 §5's closure constraint already fails at runtime
   rather than compile time. Reversible for one PR, so no ADR. If `create()` passes
   ~300 lines, group into private `setupX()` methods instead.
4. **Hold the 0.9.0 release.** Cut and mergeable as PR #395, deliberately not
   landed: the owner wants to play the gate before it reaches players.

## Verification notes

- **The gate's cost invariant failed on its first run and found a real dead end.**
  It asserts a gate never costs more than its region's smallest single delivery.
  Greybridge's cheapest route paid 45c against the 50c gate, so a courier down to
  nothing with only `writ-to-northcairn` left would have finished it 5c short,
  with no work remaining and no way on. Raised that reward to 50c. This is the
  argument for writing the guard as a test rather than a comment: the reasoning
  was right and the numbers were not.
- **Neutralizing the gate inside `gatewayBlockedBy` produced unreachable code that
  the build rejects**, so the only valid neutralization was in the region data.
  Worth knowing: a guard that is a single early return cannot be neutralized in
  place under this repo's lint settings.
- `travel.spec.ts` failed exactly as predicted when the gate landed, which was
  the intended proof that the gate reaches the browser. It now seeds past the
  gate via a new `seedUpgrades()` helper.
- Slice six's three new guards were each neutralized and watched to fail. All 29
  of its tests passed first time, which per trap 7 meant nothing until then.
- Both slices ran the full browser suite, not just the arc.

  that a completionist will never see the gate: `full-arc` needed no change
  because it already buys affordable upgrades at home. If the gate should actually
  bite, the lever is a more expensive requirement or a second gate later in the
  arc. That is a playtest question and should ride along with the next pass.
- **The human playtest did not reach the Wayfinder ring, the capstone cue, the
  full arc, or the per-frame cue collisions.** A clean pass is easy to over-read;
  the report's "does NOT establish" section exists to stop that, and #361 was
  deliberately left open rather than swept up in the good news.
- **The save direction still has no pure counterpart.** `restoreRunState` covers
  the load path; `save()` builds an 18-field snapshot literal inline. A pure
  `buildSnapshot()` would make round-trips testable and is plausibly the enabler
  the contract cluster needs. It would not shrink the file much, which is why it
  keeps losing to slices that do.
- **Trap 7 held again this session and trap 1 nearly did.** Every new guard passed
  on first run in both PRs. Neutralization is the only reason any of it is
  trustworthy.
