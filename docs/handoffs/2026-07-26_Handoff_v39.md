## Decisions taken

1. **Extract by shared state, never by shared name.** The plan in #392 proposed
   taking the fifteen `refresh*` methods together. Measuring showed that was
   wrong: they share a prefix and nothing else, and their logic already lives in
   pure builders under `src/systems/`. Every slice since was chosen by counting
   the methods outside a cluster that touch its fields.
2. **Prefer `src/systems/` to a controller when the logic needs no scene
   services.** The coverage gate measures `src/systems/**` and excludes scenes, so
   a pure module gets gated coverage and needs no host at all.
3. **Do not move widely-read state.** `skills` has fourteen readers,
   `state.ledger` about fifteen. `SpendController` drives them through host
   setters instead, grouping related writes into one call so a purchase cannot
   half-apply.
4. **Keep the Phaser runtime out of controllers.** Phaser cannot be imported under
   the `node` test environment, so a module that calls
   `Phaser.Input.Keyboard.JustDown` cannot be unit tested at all. Taking the key
   check through the host costs one member and is the whole reason two of these
   controllers have tests.
5. **Never reuse a preview server the run did not start.** A full build is 2.6
   seconds against a ~100 second suite, measured, so reuse was buying nothing
   worth the risk.

  left `board-confirm.spec.ts` green, despite that spec asserting the armed state
  directly. Playwright had reused another checkout's preview server and skipped
  the build. Re-run against a fresh build, the same neutralization fails
  correctly: the spec was always sound. Now trap 6, and fixed in #400.

  decoy `vite preview` was left on 4173 serving a stale build. Without an override
  the run now fails loudly; with `PREVIEW_PORT=4273` it builds fresh and the
  neutralized guard fails as it should.

  ids that do not exist. One failed, which is the only reason it was noticed. Now
  trap 7.
- **Four real coverage holes found across the five slices**, each a path where the

  Esc, `MilestoneController.restore()`, `resetForNewRun()` (which is #291's fix),
  and the maxed-skill vs no-points-banked refusal distinction. The standing
  summary: **this file's surfaces are verified on the path that creates them, not
